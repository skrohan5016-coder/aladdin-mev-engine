# F4 Acceptance Contract

F4 is accepted only when one exact source head and its current GitHub synthetic merge independently satisfy every requirement below.

## Required implementation

- exact accepted F3 parent identity;
- chain-bound native/ERC-20 asset identity;
- directional, time-bounded, checked-`uint256`, ceiling valuation;
- valuation book equal to the exact consumed conversion-pair set;
- deterministic plan steps recomputed from exact F3 route quotes;
- own-inventory or explicit recorded flash-loan funding;
- separate EIP-1559 gas, L1-data, OP Stack operator-fee, and direct-payment upper bounds without priority-fee double counting;
- exactly one of every reserve-cost category;
- independently identified simulations bound to exact state, opportunity, plan, implementation, environment, result source, and lifetime;
- full base-asset cost reconciliation;
- source-bound chain-health evidence;
- recomputed risk-budget snapshot binding exact plan, total cost, and notional;
- transitive funding, fee, reserve, valuation, simulation, health, and risk validity checked at final evidence time;
- `complete-recorded-upper-bound-no-inclusion-guarantee` labeling;
- no calldata, signing, submission, deployment, funding movement, or execution authority;
- closed F4 schemas and canonical F4 schema lock.

## Required adversarial validation

Wrong chain, asset, rate pair, extra rate, lifetime, funding, route, state digest, engine identity, implementation digest, result-source digest, simulation time, output, gas bound, reserve category, health context, risk snapshot, total cost, notional, integer domain, or decision authority must fail closed. Randomized valuation and cost reconciliation must match exact integer references.

## Required CI

Exact source head and current synthetic merge must independently pass compilation, all inherited F0-F3 tests, all F4 tests, repository policy, architecture lock, source-contract lock, F2/F3/F4 schema locks, and clean-worktree validation with immutable actions, read-only permissions, non-persisted credentials, fixed hosted-runner semantics, and no execution-wrapper bypass.

F4 acceptance does not authorize networking, credentials, production model approval, live simulation, transaction construction, signing, funding, bundle submission, deployment, inclusion, or trading.
